## Research question

In the tested six-turn Qwen3-30B-A3B conversation, does TTFT grow with cumulative prompt length when llama.cpp reuses the in-RAM KV prefix?

*(Original wording, kept as history: "Does time-to-first-token grow with conversation length when the KV prefix is reused?")*

## Hypothesis

[HYPOTHESIS] (falsified) Prefill dominates a long conversation, so a disk KV cache would give 'over 100x' on TTFT.

*Audit reading (2026-10-11):*
- **Tested premise.** Cumulative conversation history would make TTFT grow in the ordinary same-session use case. That premise is not observed when llama.cpp's in-RAM prefix reuse is active.
- **The '>100x' figure** was a historical engineering estimate of a disk KV cache against a no-cache baseline, not a measured disk-vs-RAM result. EXP-014 did not benchmark a disk-backed KV cache.
- **Status.** The registry status SUPPORTED refers to the measured prefix-reuse result.

## Setup

Qwen3-30B-A3B IQ2_S, six turns of different text, with and without prefix reuse.

*Audited setup (2026-10-11), from `raw/records.jsonl`:*
- **Run.** Qwen3-30B-A3B IQ2_S; runtime binary `llama-noomp@ecd06508`; CPU backend; 4 generation threads, 12 batch threads (Intel Core i5-1340P, 16 GB class machine, Windows).
- **Benchmark.** A six-turn `argine benchmark --conversazione 6` run: turn 1, then 1+2, then 1+2+3, with different text per turn. The same historical conversation was measured with and without prefix reuse.
- **One record.** Both condition series (`con_cache`, `senza_cache`) are in **one** `benchmark_conversazione` record (2026-10-02 22:02:21, 343 s duration). There is no conversation-level replication.
- **Order.** No randomized or rotated condition order was established. Condition order is not encoded in the archived record, and the historical source says only "the same conversation twice".
- **Prompt-footprint matching rule.** At every turn, with-reuse `prompt_tokens` + `cached_tokens` = without-reuse `prompt_tokens` (188 / 444 / 697 / 950 / 1207 / 1467). The two conditions represent the same cumulative prompt footprint at each turn; with reuse, the archived metrics split it into cached and processed prompt tokens.
- **Protocol.** EXP-014 does not follow the Argine2 reproducibility protocol, which postdates it.

## Result

[MEASURED] with reuse TTFT 5.03 / 5.62 / 4.78 / 5.05 / 4.86 / 5.12 s up to 1467 tokens; without reuse it grows to 40.12 s (7.8x at turn 6). *(Original wording: 7.8x is the turn-6 within-benchmark contrast only; see the audited table and reading below.)*

**Audited table (2026-10-11),** from the archived values; the ratio is TTFT without reuse divided by TTFT with reuse:

| turn | total prompt footprint | with reuse: processed prompt tokens | with reuse: cached tokens | TTFT with reuse (s) | TTFT without reuse (s) | observed ratio |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 188 | 188 | 0 | 5.0281 | 5.1057 | 1.02x |
| 2 | 444 | 256 | 188 | 5.6227 | 10.9618 | 1.95x |
| 3 | 697 | 187 | 510 | 4.7797 | 18.1880 | 3.81x |
| 4 | 950 | 166 | 784 | 5.0503 | 24.5730 | 4.87x |
| 5 | 1207 | 171 | 1036 | 4.8639 | 32.1469 | 6.61x |
| 6 | 1467 | 174 | 1293 | 5.1217 | 40.1159 | 7.83x |

- **With reuse:** TTFT remained within 4.78–5.62 s across the six tested turns while cumulative prompt footprint increased from 188 to 1467 tokens. This is an observed range in one conversation: no constancy, zero slope or statistical equivalence across turns is claimed.
- **Without reuse:** TTFT increased monotonically from 5.11 to 40.12 s as the cumulative prompt grew from 188 to 1467 tokens.
- **Turn 6:** 1467 total = 174 processed + 1293 cached; 5.1217 s with reuse vs 40.1159 s without; observed within-benchmark contrast ≈7.83x (historically rounded 7.8x).
- **TTFT vs `prompt_ms`:** the archived TTFT closely tracks the recorded prompt-processing duration (`prompt_ms`) in this benchmark, but TTFT remains the reported endpoint metric. No additional timing decomposition is established.

## Interpretation

*[Historical interpretation, narrowed by the 2026-10-11 audit: "llama.cpp's in-RAM prefix reuse already covers the use case; the disk KV cache project was cancelled." This is superseded by the wording below.]*

[DERIVED, HISTORICAL DECISION] For the tested ordinary same-session growing-conversation case, llama.cpp's existing in-RAM prefix reuse already removed the cumulative-prefix TTFT growth that had motivated the proposed disk-KV project. Argine therefore cancelled that project as an engineering priority. This is a project-prioritization conclusion, not experimental evidence that persistent/disk-backed KV state has zero value. The historical source itself names distinct use cases where it could still matter: resuming after a restart and switching among different conversations. These were not tested.

[SUPPORTED, HISTORICAL] **Audit closure (2026-10-11).**
- SUPPORTED is retained.
- Within this one six-turn benchmark, prefix reuse prevented cumulative-prefix TTFT growth from appearing across the tested range (188 → 1467 tokens; observed 4.78–5.62 s with reuse vs 5.11 → 40.12 s without).
- 7.8x is the observed turn-6 within-benchmark contrast only. It is not an average, replicated, general or disk-cache speedup.
- Disk-backed KV persistence was not benchmarked, and the '>100x' disk-KV estimate was not a measured effect.
- Cancelling the disk-KV project was an engineering prioritization decision for the tested normal conversation use case. Restart, persistence, eviction and cross-conversation cases remain untested.
- No rerun is required for historical closure ([historical audit](../../docs/research/HISTORICAL-AUDIT-EXP011-018.md)).

## Limitations

[LIMITATION] One conversation.

[LIMITATION, historical audit 2026-10-11]
1. One conversation only.
2. One model: Qwen3-30B-A3B IQ2_S.
3. One historical benchmark invocation / raw record.
4. No conversation-level repetitions.
5. Condition order is not encoded in the archived record, and no immutable historical source states it.
6. No randomized or rotated condition order.
7. 7.8x is the turn-6 observed contrast, not a replicated or general effect size.
8. No disk-backed KV implementation was benchmarked.
9. Restart, persistence, eviction and switching between different conversations were not tested.
10. Memory pressure. The historical invocation ran under substantial system-memory pressure: the plan warned that the 11 GiB budget exceeded the 8.23 GiB of RAM free at start; minimum system-available memory was 0.18 GiB; system disk reads totalled 13.8 GB over 343 s. Because the two condition series were not replicated or rotated, machine-state/order effects cannot be excluded as contributors to the exact numeric ratio. This does not discard the observed pattern. The similar first-turn TTFTs (5.03 vs 5.11 s) are descriptive, not a formal control for order effects.
11. TTFT and `prompt_ms` are separate recorded metrics, even though they closely track each other in this invocation.
12. EXP-014 predates the Argine2 reproducibility protocol.
